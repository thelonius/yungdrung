# Yungdrung — трекер задач

Задача здесь — это цепочка шагов, которые идут по очереди, и у каждого шага есть
дата контроля. Когда дата наступает, трекер спрашивает про шаг; после отметки
«сделан» показывается следующий, а когда закрыты все шаги, закрывается и задача.
Рядом, в том же хранилище, живёт база знаний: имя в тексте задачи пишется как
`[[Василий Говнов]]` и кликом открывает заметку про него.

Устройство — четыре слоя, связь идёт только сверху вниз:

1. **Вольт `.md`** — папки `Задачи/` и `База/`. Единственный источник правды.
   Обычные текстовые файлы: работают без сети, читаются любым редактором,
   версионируются git.
2. **Движок `engine.py`** — считает просрочки и пишет шаги. Единственный, кто
   вообще пишет шаги и даты; руками их править не надо, а интерфейсы поверх только
   зовут его команды. Никакой модели внутри нет, всё считается арифметикой по датам.
3. **Интерфейсы** — Obsidian с плагином Bases (обзор, таблицы, навигация по
   ссылкам) и чат-бот. Сменные: если убрать их целиком, трекер продолжит работать.
4. **cron** — будит движок по расписанию, чтобы напоминания приходили сами.

Подробнее про архитектуру и почему выбрано именно так — в
[CLAUDE.md](CLAUDE.md). Журнал работы, чек-листы развёртывания и результаты
проверок — в [ПРОТОКОЛ.md](ПРОТОКОЛ.md).

## Установка на Windows

Пошагово, с нуля. Ставится один раз, дальше обновления приезжают через `git pull`.

### 1. Python

Скачать с [python.org/downloads](https://www.python.org/downloads/) версию 3.11
или новее, запустить установщик. Если Python уже стоит и версия не ниже 3.8 —
ставить заново не нужно, движок заработает и на ней.

**В первом же окне установщика отметить галочку «Add python.exe to PATH».** Она
внизу, её легко проскочить. Без неё Windows не будет знать, где лежит Python, и
ни одна команда из этой инструкции не заработает — а лечится это переустановкой.

Дальше нажать «Install Now» и дождаться конца.

Проверить: открыть «Командную строку» (Win+R, набрать `cmd`, Enter) и ввести

```
python --version
```

Должно ответить `Python 3.11.x` или новее. Если пишет, что команда не найдена,
галочку не поставили — переустановить Python с ней.

> На Windows команда обычно `python`. На маке и в Linux — `python3`. Если
> `python` не отвечает, попробуйте `python3` или `py -3`; дальше в инструкции
> подставляйте то, что сработало.

### 2. Git for Windows и клонирование репозитория

Скачать с [git-scm.com/download/win](https://git-scm.com/download/win), поставить
со всеми настройками по умолчанию — менять там ничего не нужно.

Затем в командной строке перейти в папку, где будет жить трекер, и забрать код:

```
cd %USERPROFILE%
git clone https://github.com/thelonius/yungdrung.git
cd yungdrung
```

Репозиторий приватный, поэтому при клонировании откроется окно авторизации
GitHub. Войти под аккаунтом, у которого есть доступ (`thelonius`) — либо через
браузер в этом окне, либо личным токеном вместо пароля. Пароль от GitHub в этом
окне не подойдёт, GitHub их больше не принимает.

После этой команды появится папка `yungdrung` — она же и репозиторий, и хранилище
задач.

### 3. Зависимости

Не выходя из папки `yungdrung`:

```
pip install -r requirements.txt
```

Команда поставит всё, что нужно движку. Главное из этого — PyYAML: им движок
читает и пишет свойства задач. Без него `engine.py` откажется стартовать и прямо
об этом скажет.

### 4. Obsidian

Скачать с [obsidian.md](https://obsidian.md/) и установить. Программа бесплатная,
платить за неё не обязательно даже при работе.

При первом запуске выбрать **«Open folder as vault»** и указать ту самую папку
`yungdrung`, которая появилась после `git clone`. Не создавать новое пустое
хранилище: задачи уже лежат в этой папке, Obsidian должен открыть её, а не
завести рядом свою.

Потом включить встроенный плагин Bases — он рисует задачи таблицей:

Настройки (шестерёнка слева внизу) → **Core plugins** → найти **Bases** →
переключатель включить.

После этого в списке файлов появится `Задачи.base`. Открыть его — увидите таблицу
задач с тремя вкладками: «Доска» (всё, сгруппировано по статусу), «Требует
внимания» (незакрытое) и «Буксуют» (шаги, которые переносились три раза и больше).

### 5. Проверка, что всё встало

В командной строке, в папке `yungdrung`:

```
python engine.py list
```

Ответ — список задач в формате JSON, примерно такой:

```json
{
  "today": "2026-08-13",
  "tasks": [
    {
      "task": "Замена подшипника в колесе",
      "status": "overdue",
      "category": ["сервис"],
      "steps_done": 1,
      "steps_total": 2,
      "current": "Снять колесо, заменить"
    }
  ]
}
```

Если задачи перечислились — Python, зависимости и вольт на месте, установка
закончена. Выглядит громоздко, потому что это машинный формат: его читает бот, а
человек смотрит на те же задачи в Obsidian.

Что может пойти не так:

| Что написало | Что делать |
|---|---|
| `'python' is not recognized...` | Python поставлен без галочки PATH — переустановить с ней. Или попробовать `py -3 engine.py list` |
| `нужен pyyaml: pip install pyyaml` | Пропущен шаг 3, выполнить `pip install -r requirements.txt` |
| `нет папки задач: ...` | Команда запущена не из папки `yungdrung`. Сделать `cd` в неё |

## Команды движка

Все команды запускаются из папки репозитория и отвечают JSON-ом. Задача
указывается **куском имени файла**, целиком писать не надо и регистр не важен:
`грант` найдёт «Заявка на грант ФПГ». Если под кусок подходит несколько задач,
движок откажется гадать и перечислит их. Шаг указывается его номером `id` из файла.

| Команда | Пример | Что делает |
|---|---|---|
| `next` | `python engine.py next` | Что требует внимания сегодня: просроченные шаги, шаги на сегодня и шаги без даты. Сверху самые давние. Отдельным списком — буксующие |
| `list` | `python engine.py list` | Все задачи со статусом, категориями и текущим шагом |
| `show` | `python engine.py show грант` | Одна задача целиком: свойства, все шаги и полная история отметок |
| `done` | `python engine.py done грант 2` | Шаг сделан. Открывается следующий; если у него не было даты контроля, движок ставит сегодня, чтобы шаг не потерялся |
| `notdone` | `python engine.py notdone подшипник 2 --reason "мастер в отпуске"` | Шаг не сделан, остаётся открытым. Спросит завтра |
| `defer` | `python engine.py defer грант 2 --to 2026-08-20 --reason "уехал"` | Перенести шаг на конкретную дату |
| `skip` | `python engine.py skip грант 3 --reason "решили без фонда"` | Снять шаг: задача пошла другим путём. Шаг закрывается, но не как выполненный |
| `refresh` | `python engine.py refresh` | Пересчитать статусы во всех задачах |

`--reason` необязателен везде, где встречается, но его стоит писать: причина
попадает в историю шага и потом видна в `show` и в сборке `next`.

Есть ещё общий флаг `--today` — подставить другую сегодняшнюю дату, чтобы
посмотреть, что движок скажет в другой день. Нужен для проверок, в обычной работе
не используется:

```
python engine.py --today 2026-09-01 next
```

### `notdone` и `defer` — в чём разница

Обе команды двигают дату вперёд и обе оставляют шаг открытым. Разница в том, **кто
выбирает новую дату**, и она важнее, чем кажется.

**`notdone`** — «не получилось». Причина внешняя и от вас не зависит: не
дозвонились, человек в отпуске, не было времени. Дату вы не выбираете, движок сам
переспросит завтра. Смысл в том, что дело никуда не делось и решать его всё равно
придётся, поэтому шаг возвращается на глаза, а не уходит из вида.

```
python engine.py notdone подшипник 2 --reason "не дозвонился"
```

Если завтра неудобно, можно назвать другой день тем же `--to`, но по умолчанию
это именно «спроси меня снова завтра».

**`defer`** — «перенести на такое-то число». Дату назначаете вы, и она обязательна.
Это осознанное решение: договорились на понедельник, ждём документ до пятницы,
до отпуска смысла дёргать нет.

```
python engine.py defer грант 2 --to 2026-08-20 --reason "Говнов в отъезде"
```

Коротко: `notdone` — «не вышло, напомни завтра», `defer` — «займусь двадцатого».

### Счётчик буксования

Каждый `notdone` увеличивает счётчик у шага. Когда он доходит до **трёх**, шаг
попадает в отдельный список `stalled` в выдаче `next`, помечается флагом `stalled`
в свойствах задачи и всплывает во вкладке «Буксуют» в Obsidian.

Это не ошибка и ничего не блокирует. Просто три переноса подряд означают, что
дело не двигается само, и четвёртая дата его не сдвинет — нужен другой ход:
позвонить другому человеку, отдать задачу кому-то ещё или снять шаг через `skip`.
`defer` счётчик не трогает: перенос на выбранную дату — нормальный ход работы, а
не пробуксовка.

## Как устроена задача

Одна задача — один файл `.md` в папке `Задачи/`. Сверху, между строчками `---`,
идут свойства (это frontmatter, Obsidian показывает его отдельной панелькой), ниже
— свободный текст.

Завести задачу можно руками: скопировать файл из `Задачи/`, переименовать и
переписать. В командах и выдаче движка задача зовётся по имени файла, так что
называть файл стоит по-человечески.

```yaml
---
schema: 1                     # версия схемы, не трогать
type: task                    # обязательно: файлы без него движок не видит
title: Заявка на грант ФПГ
created: 2026-08-05
tags:                         # категории; по ним группируется таблица
  - гранты
  - документы

# --- всё ниже до steps пересчитывает движок, руками не заполнять ---
status: ждёт                  # просрочена / сегодня / ждёт / закрыта
current_step: Отправить на согласование
control_date: 2026-08-15      # дата контроля текущего шага
progress: 1/3
stalled: 0                    # сколько раз текущий шаг не сделали

steps:
  - id: 1                     # номер, им шаг указывается в командах
    title: Собрать пакет документов
    status: done              # pending / done / skipped
    control_date: 2026-08-08
    completed_date: 2026-08-07
    log:                      # история отметок, пишет движок
      - date: 2026-08-07
        event: done
  - id: 2
    title: Отправить на согласование
    status: pending
    control_date: 2026-08-15
    completed_date: null
    log:
      - date: 2026-08-13
        event: defer
        was: 2026-08-13
        to: 2026-08-15
        reason: Говнов в отъезде, попросил перенести
  - id: 3
    title: Дождаться решения фонда
    status: pending           # у последнего шага даты может не быть:
    control_date: null        # движок поставит её, когда закроется шаг 2
    completed_date: null
    log: []
---

Здесь свободный текст. Сюда же пишутся ссылки на заметки базы знаний:
отправить документы [[Василий Говнов]], подшипник нужен [[6805]].
```

Заводя задачу руками, достаточно написать `type`, `title`, `tags` и список шагов
с `id`, `title` и `status: pending`. Сводку сверху (`status`, `current_step`,
`progress`, `stalled`) заполнит движок — она нужна затем, что Bases читает только
свойства верхнего уровня и внутрь списка шагов не заглядывает. Чтобы движок
проставил её сразу:

```
python engine.py refresh
```

`refresh` стоит гонять и просто так, по утрам: задача становится просроченной
оттого, что прошёл день, а не оттого, что её кто-то трогал. Файлы, где ничего не
поменялось, при этом не переписываются.

### Ссылки `[[...]]` работают и в названиях шагов

Написанный в названии шага `[[Василий Говнов]]` кликается, и в заметке Василия
появляется обратная ссылка. Работает это не напрямую: сам Obsidian ссылки в
свойствах не разбирает, но движок дублирует шаги списком в тело заметки, а там
это уже обычный markdown.

Поэтому список шагов в теле трогать руками не нужно — он между маркерами
`<!-- шаги -->` и переписывается движком при каждой записи. Всё, что вы напишете
до или после этого блока, сохранится.

## Как менять шаги уже заведённой задачи

Отметки — командами: `done`, `notdone`, `defer`, `skip`. А вот **состав** шагов
(добавить, убрать, переименовать, поменять местами) правится руками в Obsidian, в
свойстве `steps`. Движок подхватит изменения при следующем запуске и пересчитает
статус сам.

Одно предостережение. `steps` — это YAML, и он чувствителен к отступам и
скобкам. Если ошибиться, задача перестанет читаться движком: она пропадёт из
`list`, `next` и утренней сборки. Чтобы такое не проходило незамеченным, движок
докладывает о нечитаемых файлах:

```
python engine.py list
```

```json
"broken": [{"file": "Заявка на грант.md", "error": "line 35: expected ',' ..."}]
```

Если задача вдруг «пропала» — посмотрите сюда, в `error` будет номер строки.

## Где лежат ваши задачи

Задачи и заметки живут **только на вашем компьютере** и в репозиторий не
отправляются. Папки `Задачи/` и `База/` git намеренно не отслеживает: ваши
рабочие дела не должны уезжать на GitHub, а обновления кода не должны спорить с
вашими файлами.

Практическое следствие: `git pull` приносит новую версию движка и никогда не
трогает то, что вы завели. Резервная копия задач — ваша забота: для этого есть
выгрузка в Excel (`export`), а сама папка вольта копируется как обычная папка.

Три задачи-примера и две заметки лежат в `примеры/`. Если хочется посмотреть, как
всё устроено на заполненных данных, скопируйте их в `Задачи/` и `База/`, а потом
удалите — на реальную работу они не влияют.

## Мелочи, которые могут пригодиться

- Папка вольта по умолчанию — та, где лежит `engine.py`. Если задачи должны жить в
  другом месте, путь задаётся переменной окружения `YUNGDRUNG_VAULT`.
- Задачами считаются только файлы из `Задачи/` со свойством `type: task`. Файл со
  сломанным frontmatter движок пропустит и напишет об этом, но работать не
  перестанет.
- `refresh --force` переписывает все файлы задач, даже неизменившиеся. Это нужно
  после смены схемы, в обычной работе не запускать.
- Обновление кода — `git pull` в папке репозитория.
- Три файла в `Задачи/` и две заметки в `База/` — примеры, приехавшие вместе с
  кодом. Они лежат в репозитории, поэтому их можно удалить, когда появятся свои.
