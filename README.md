# Yungdrung — трекер задач

Задача здесь — это цепочка шагов, которые идут по очереди, и у каждого шага есть
дата контроля. Когда дата наступает, трекер спрашивает про шаг; после отметки
«сделан» показывается следующий, а когда закрыты все шаги, закрывается и задача.
Рядом, в том же хранилище, живёт база знаний: имя в тексте задачи можно связать
с записью и открыть её из веб-интерфейса.

Устройство — четыре слоя, связь идёт только сверху вниз:

1. **Стор** — единственный источник правды. Задачи — в SQLite (`стор.db`),
   записи базы знаний — в той же базе (раньше жили в `База/*.md`, миграция
   прозрачная). Рядом на диске: `Настройки.json`, `Шаблоны.json`, вложения.
   Данные заказчика в git не версионируются — только код.
2. **Движок** — считает просрочки, статусы и даты, единственный пишет задачи и
   шаги. Без LLM. Чистые вычисления — в `domain/`, операции над стором (лента,
   отметки, запись) — в `core/`; `engine.py` — их CLI-адаптер и дом для команд,
   которые ещё не переехали. На выходе JSON — для любой оболочки.
3. **Интерфейсы** — сменные: **веб-морда** (`server.py` + `static/`) — основной
   способ работать; CLI движка — для бота и скриптов; чат OpenClaw — позже.
4. **cron** — будит `remind.py` по расписанию, чтобы напоминания приходили сами.

Подробнее про архитектуру — в [CLAUDE.md](CLAUDE.md). Журнал работы и проверки —
в [PROTOCOL.md](PROTOCOL.md). Контракт «оболочка ↔ ядро» — в [CONTRACT.md](CONTRACT.md).

## Веб-интерфейс

После запуска `python server.py` открывается браузер на `http://127.0.0.1:8765`.
Сервер (FastAPI, `api/`) сам в стор не пишет — только зовёт ядро (см. `CONTRACT.md`).
Описание типизированного API — на `http://127.0.0.1:8765/docs`; прежние
маршруты `/api/*` живут для старых страниц и уходят вместе с ними.

| Адрес | Назначение |
|-------|------------|
| `/` `/лента` | Что сегодня: лента, разбор завала, отметки шагов |
| `/новая` | Создать задачу (шаги, даты, подшаги, ссылки на базу знаний) |
| `/задача` | Карточка задачи: правка, вложения, отметки |
| `/задачи` | Все задачи по статусам |
| `/шаблоны` | Шаблоны и повторения |
| `/база` | База знаний |
| `/база/запись` | Редактор записи базы знаний |
| `/настройки` | Теги, причины, бэкапы, экспорт |
| `/архив` | Закрытые и отменённые задачи |

Формы заточены под ТЗ: разбор дат на сервере («завтра в полдесятого», «+3»),
подтверждённые ссылки на базу знаний, подшаги `par`/`seq`, шаблоны, вложения.
Отдельные программы для просмотра задач не нужны.

## Установка на Windows

Пошагово, с нуля. Ставится один раз, дальше обновления приезжают через `git pull`.

### 1. Python

Скачать с [python.org/downloads](https://www.python.org/downloads/) версию 3.11
или новее. **В первом окне установщика отметить «Add python.exe to PATH».**

Проверить в командной строке (`Win+R` → `cmd`):

```
python --version
```

Должно ответить `Python 3.11.x` или новее.

> На Windows обычно `python`. На маке и в Linux — `python3`. Если `python` не
> отвечает, попробуйте `py -3` или `python3`.

### 2. Git for Windows и клонирование

Скачать с [git-scm.com/download/win](https://git-scm.com/download/win), поставить
со всеми настройками по умолчанию.

```
cd %USERPROFILE%
git clone https://github.com/thelonius/yungdrung.git
cd yungdrung
```

### 3. Зависимости

```
pip install -r requirements.txt
```

### 4. Запуск

```
python server.py
```

Откроется браузер с лентой «Что сегодня». Сервер слушает только `127.0.0.1` —
снаружи недоступен.

Другой порт: `python server.py --port 9000`. Без автозапуска браузера:
`python server.py --no-open`.

### 5. Проверка движка (необязательно)

```
python engine.py list
```

Ответ — JSON со списком задач. Пустой список на новом сторе — нормально.
Создайте задачу через `/новая` или `python demo.py` для демо-данных.

| Что написало | Что делать |
|---|---|
| `'python' is not recognized...` | Python без PATH — переустановить с галочкой |
| `нужен pyyaml: pip install pyyaml`, `нужны fastapi и uvicorn` | Выполнить `pip install -r requirements.txt` |
| Порт занят | `python server.py --port 9000` |

## Команды движка (CLI)

Все команды — из папки репозитория, ответ JSON. Задача указывается **куском
названия**: `грант` найдёт «Заявка на грант ФПГ». Шаг — номером `id`.

| Команда | Пример | Что делает |
|---|---|---|
| `next` | `python engine.py next` | Что требует внимания сегодня |
| `list` | `python engine.py list` | Все задачи со статусами |
| `show` | `python engine.py show грант` | Одна задача целиком |
| `done` | `python engine.py done грант 2` | Шаг сделан |
| `notdone` | `python engine.py notdone подшипник 2 --reason "..."` | Не сделан, спросит завтра |
| `defer` | `python engine.py defer грант 2 --to 2026-08-20` | Перенести на дату |
| `skip` | `python engine.py skip грант 3 --reason "..."` | Снять шаг |
| `undo` | `python engine.py undo грант 2` | Отменить последнее сегодняшнее действие над шагом |
| `refresh` | `python engine.py refresh` | Показать сводку по всем задачам (только чтение) |
| `export` | `python engine.py export --to выгрузка.xlsx` | Excel-выгрузка |

`--reason` попадает в историю шага. Флаг `--today` подставляет другую дату для
проверок: `python engine.py --today 2026-09-01 next`.

### `notdone` и `defer`

**`notdone`** — «не получилось», движок переспросит завтра. **`defer`** — перенос
на конкретную дату, которую выбираете вы. `defer` счётчик буксования не трогает.

### Буксование

Три `notdone` подряд — шаг помечается `stalled` и всплывает в ленте и в разделе
буксующих. Это сигнал, что дело застряло, а не ошибка.

## Где лежат данные

Всё живёт **только на компьютере заказчика**. `стор.db`, `Настройки.json`,
`Шаблоны.json`, папка `вложения/` — git их не отслеживает.

`git pull` приносит новый код и не трогает задачи. Резервные копии — в настройках
веб-интерфейса (`/настройки`) или `python engine.py` + `backup.py`.

Путь к стору по умолчанию — папка репозитория. Другое место: переменная
окружения `YUNGDRUNG_VAULT`.

Демо-данные: `python demo.py` (тег «демо»), убрать: `python demo.py --clean`.
Примеры старого markdown-формата — в `examples/`, только для справки.
